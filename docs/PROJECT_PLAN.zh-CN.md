# Windows 项目完整规划

日期：2026-11-15。基线：上游 2.4.0 / 87de3b6。状态：规划就绪，Windows 开发环境验收未通过。

## 目标与用户流程

首个交付面向本机摄影编辑：打开受支持 RAW → 选择胶片/相纸 → 调整曝光与效果 → 裁切和旋转 → 保存编辑 → 导出 → 重启恢复编辑。失败输入、失败导出与取消操作不能破坏当前照片或既有文件。

首版覆盖 Windows x64、现有 Vulkan 后端、Qt 编辑器、sRGB SDR 预览与现有 TIFF/PNG/JPEG 输出能力。优先验证本机 RTX 3060 Laptop GPU；AMD 集成显卡作为后续设备覆盖，不默认宣称所有 GPU 都支持。Windows 版本、驱动、Qt 与编译器版本在运行验收时记录。

## 架构与范围决策

- 引擎：复用 engine/src/core 与 pipeline，平台运算保留 Vulkan；不改 81×5 nm 光谱轴与实测材料数据。
- 输入：复用 LibRaw，明确输出线性 RGB、白平衡、曝光和色彩空间。
- 编辑器：以 windows_UI 的 Qt 路径作为首个可运行交付。desktop/ 的 Tauri 路径保留；它是长期候选，选型在核心验收后评估，不同时扩展两套界面。
- 边界：参数走现有 C ABI；Qt 的状态、后台任务、几何、持久化与导出保持原有分层。
- 依赖：项目本地部署，不做系统级安装。复用现有校验清单；本次不增加新的全树指纹机制。
- 首版暂缓：图库平台整合、Capture One 导入、半格配对、完整胶片边框、HDR、所有 Mac 功能一比一迁移。明确拒绝未实现功能，不能静默丢弃。

| M6 性能与功能收敛 | 测冷启动、解码、上传、渲染、回读、显示、导出与显存；决定长期前端；按需求补特效 | 优化前后可复测；相关正确性门禁通过 | M3/M5 |

交付分级：M1–M4 是 Windows 核心可用交付；M5 是颜色与跨实现质量验收；M7 是实验性真实性验收。后两项不作为“已经可启动”的推论。计划顺序不承诺固定日历工期；外部样本和参考环境未到位时，先推进不依赖它们的任务。

## 工作包与责任

主执行者负责构建、集成、状态和验收；独立审查可分配给子代理，但不重复执行相同实验。人工确认主要用于真实编辑体验、目标显示器效果及发布决定。需要用户已有 RAW 时先确认可用路径；任何样本都只读使用或复制到隔离测试目录。

| 工作包 | 涉及模块 | 验证的具体失败 |
|---|---|---|
| 工具链 | engine/build-windows.ps1、windows_UI/build.ps1、setup-qt.ps1、CMakeLists 与 dependencies/ | 依赖失效、DLL 缺失、编译器混用、只编译 portable core |
| 引擎 | engine/src/gpu、pipeline、tests、tools | 数值偏差、缓存错误、对象释放错误、条带边界差异 |
| 输入输出 | engine/src/io、windows_UI/src/FrameOutput.* | RAW 解码合同偏差、ICC/位深/几何错误、覆盖文件 |
| 编辑状态 | PreviewController、EditStore、FrameCanvas、qml | 旧结果覆盖新状态、切图串参、历史或持久化丢失 |
| 发布 | windows_UI/build.ps1、许可证、.github/workflows | 依赖开发机 PATH、缺资源、缺许可证、CI 无实际覆盖 |

## 关键风险与处理

| 风险/已知障碍 | 处理与关闭证据 |
|---|---|
| 当前 Qt version check failed | 检查 qmake 实际输出、退出码、依赖 DLL 和进程 PATH；定位后最小修复，不预判为版本不匹配 |
| glslang 使用 main-tot 下载包 | 在可复现构建前确定固定 release 或源码版本，记录真实版本和官方来源 |
| 缺少真实相机 RAW | 合成图先验引擎；真实照片门禁保持待验收，不能以 mock 替代 |
| 缺 Metal/Python oracle | 保存固定输入和参数，待有匹配参考后比较；不采用 Windows 自比证明准确性 |
| Mac 与 Windows 特性分叉 | 以当前拒绝条件和功能覆盖表为准，新增功能同步参数、调用方和验证 |
| 显示 ICC/HDR 未证明 | 首版声明实际 SDR 范围；后续单独验收屏幕转换，不以嵌入 ICC 代替 |
| 多 GPU 和驱动差异 | 首先记录并验收实际选用设备，之后扩大硬件覆盖 |

## 实施约束

每项改动先定位所有调用方、配置和测试；每个检查必须能说明会发现什么失败、失败时改变什么决定。仅跑受影响检查，阶段集成时再跑完整相关套件。数值容差采用现有已验证标准；不得为通过测试放宽，也不统一收紧到 float epsilon。性能数据单列解码、引擎和写盘时间，不引用上游机器的成绩作为本机成绩。

## 发布标准

M4 交付必须包含自包含应用目录、启动步骤、功能边界、第三方许可证和实际验收记录。原照片不被修改，导出拒绝覆盖。独立机器/环境验证尚未完成则明确标为本机构建。对外发布的名称和图标按仓库商标说明处理；不在本次初始化中发布或更改品牌。
