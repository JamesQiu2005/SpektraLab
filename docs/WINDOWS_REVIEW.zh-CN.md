# SpektraLab：模型、架构与 Windows 改进计划

审读基线：87de3b6（2.4.0，2026-11-14）。本报告区分源码实现、历史验收和本机验收。

## 从问题出发

胶片照片的形成是光谱能量经感光、显影、染料吸收、相纸曝光与显影，再经观看光源或扫描得到颜色的过程。SpektraLab 将这些环节组合成可交互的数字暗房：RAW 解码后的场景线性 RGB → 胶片曝光 → 负片密度 → 放大机与相纸 → 扫描 RGB → 显示和导出。Mac 应用还实现图库、评级、变体、批量输出、胶片边框、日期和半格配对。

它继承 spektrafilm 的胶片模型、28 个实测胶片/相纸配置及打印表；本仓库的主要贡献是原生 C++/Metal 引擎和应用整合，另有 Vulkan、LibRaw 与 Windows 前端。不能把整个物理模型的原创归于此仓库。

## 模型到底计算了什么

光谱范围是 380–780 nm，5 nm 一档，共 81 档。一个染料层的透射率近似为 10 的负光学密度次方，多层密度相加。输出通道将光源光谱、透射率与感光灵敏度相乘后积分。负片到相纸和相纸到扫描色各做一次。

输入只有三个 RGB 数值，无法唯一确定 81 档光谱。引擎选择一类光谱先验，并用 Hanatos 表估计胶片曝光；光谱表在 setup 时与胶片灵敏度积分为 192×192×3 表，逐像素做插值。实际执行既有光谱积分也有预计算 LUT；区别在于 LUT 服务于具体物理阶段，并非只有一个端到端颜色滤镜。

显影曲线将对数曝光映射为染料密度；DIR 耦合、颗粒、卤化光晕等涉及通道耦合、空间扩散或随机场。135/120 等画幅决定像素对应的微米尺度，因此改变图像大小时应保持效果的物理尺度。相关源码：engine/src/core/hanatos.cpp、engine/src/core/spectral.cpp、engine/src/pipeline/pipeline.cpp。

## 优势

- 参数有明确归属：场景曝光、材料响应、打印条件、最终编辑各司其职。排查偏色或高光问题时可定位到具体阶段。
- 颗粒、光晕和扩散体现空间关系；单个逐像素 3D LUT 无法表达这类现象。
- 通过预积分、GPU 运算、setup 缓存和负片缓存减小交互成本；改相纸或打印设置时可以复用负片。
- C ABI 将前端与引擎隔离；Windows 可复用 C++ 模型和材料数据。运行时无需 Python。
- 已有大量数值、生命周期、几何、功能边界和导出测试；Windows 特效通过 Vulkan 实际渲染。

## 劣势和边界

- 光谱恢复是欠定逆问题。仓库 TRAPS.md 第 13 条记录紫色区域的结构性偏差；其中历史色差值不能当作当前 Windows 实测。相机解码矩阵和白平衡同样会改变结果。
- 实测材料曲线加近似模型，不等于完整模拟胶片化学，也不证明任意照明、曝光和扫描条件下与真实胶片一致。需要受控实拍对照。
- Mac 2.x、Qt 和 Tauri 仍存在功能与版本分叉。Windows 已通过 Vulkan 渲染场景宽容度、contrast mask、Cineon DI、片边/日期、漏光、scan HDR、场景蒙版、柔光滤镜和镜头像差；目前只有功能与合成边界测试，尚无 Metal/Python 同输入全图数值 parity。
- Vulkan 传输与调度保留同步路径，Windows 结果交付是独立 CPU RGBA16，并不是可直接显示的 GPU 纹理。高分辨率预览可能受回读和复制影响。
- Qt 当前显示为 8-bit SDR sRGB；完整显示器 ICC、广色域和 HDR 验收尚未建立。文件带 ICC 标签不证明屏幕显示正确。
- 外部 Python 参考与私有 RAW 样本不在仓库中。本地测试通过不能代替 Metal 全图一致性，更不能代替真实胶片准确性。
- 多套前端、平台脚本和历史说明增加维护负担；首次安装脚本与当前源码接口已经存在漂移。

## 改进顺序与验收

| 顺序 | 工作 | 验收证据 |
|---|---|---|
| P0：本次 | 修通现有 Qt/Vulkan 构建；更新失效依赖清单；明确 C/C++ 编译器与 CMake 变量 | 干净构建目录配置与 Release 构建成功；运行 CTest；可见窗口启动 |
| P1：输入输出正确性 | 固定 RAW 解码/白平衡/色彩空间契约，建立可分发的小 RAW 与合成参考集 | 不同相机、曝光、饱和色和裁切的端到端测试；导出读回确认位深、ICC、尺寸和像素 |
| P1：跨后端一致性 | 同输入、同参数、关闭随机项，比较 Vulkan 与 Metal/Python | 全图误差、边界误差、颜色差异和失败样本可复现；随机项另验分布与空间统计 |
| P2：Windows 产品完整性 | 先补显示色彩管理和高频编辑能力，再按实际需要补跨后端数值 parity | 预览/导航/导出一致；不同显示配置验收；异常输入给出明确错误 |
| P2：性能 | 分别量测解码、上传、计算、回读、显示和写盘 | 同图同设备交错测量冷/热渲染、缓存重印及峰值内存，按瓶颈选择优化 |
| P3：科学校准 | 同场景数码与胶片、标准色卡、多曝光、多光源受控对照 | 颜色/密度误差与颗粒、光晕空间特征报告；清楚标注适用条件 |
| P3：维护 | 选定长期 Windows 主前端，减少重复入口，增加 Windows CI | 新机器能按文档构建；CI 失败不会悄悄退化为仅 portable core |

本次选 Qt 是因为它已接入原生 RAW、编辑状态和实际导出；重新搭建界面无法解决模型和平台验收缺口。
