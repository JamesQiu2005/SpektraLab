# Procedure: all-pair minilab coverage

This is the reproducible procedure for extending
`engine/resources/minilab/` from the one qualified Portra pair to every eligible
film/paper pair. The model rules and the definition of complete coverage are
`SOP.md`; the assignment is `DEEPSEEK-HANDOFF.md`; the live coverage table is
`COVERAGE.md` (generated by `report.py`, never hand-edited).

Where this procedure and a script disagree, the script is the truth and the
script is wrong until it has reproduced the frozen canary.

## 1. Scope

| route | pairs | disposition |
|---|---:|---|
| colour negative × colour paper | 136 | independently qualified in sRGB **and** ProPhoto = 272 tables |
| B&W negative × silver paper | 4 | existing silver path, verified, never a colour minilab |
| reversal film × paper | 36 | existing paper bypass, verified, never a colour minilab |
| colour/silver model mismatch | 49 | recorded incompatible, pairing rule preserved |
| **total 25 × 9** | **225** | every row accounted for |

A pair is **qualified** only when both calibration spaces have passed the
numeric gates *and* a person has inspected the colour-chart sheet; a pair is
**staged** only when its table and a catalog entry are in
`engine/resources/minilab/`. "272 files exist" is not the criterion.

## 2. Environment lock

Recorded in every job's `manifest.json` and in `run/reports/overlay.json`:

- production checkout commit (the branch carrying `engine/src/core/minilab.cpp`);
- oracle dylib / metallib / constants-blob SHA-256;
- the six patch scripts from
  `engine/performance/2026-10-24/provenance.json` (verified against their
  recorded SHA-256 before use);
- every research source that decides a bake (`v2/*.py`, `study/*.py`);
- profile files (named and inherited), datasets, and the input photograph;
- Python 3.12.11, numpy 2.5.4, scipy 1.18.1, colour-science 0.4.7;
- the BLAS thread environment as inherited (one child process at a time; no
  thread-count override, because the frozen canary is byte-exact under the
  default and a thread change is not worth re-proving).

The oracle is built from the **recorded revision**, not from the current tree:

```sh
SCRATCH=/private/tmp/minilab-bake-oracle
git archive unpublished-revision engine | tar -x -C "$SCRATCH"
cp -R "$SCRATCH/engine" "$SCRATCH/engine-baseline"
for p in research/Metamerism/study/patch_experiment.py \
         research/Metamerism/v2/patch_v2_print.py \
         research/Metamerism/v2/patch_v2_minilab.py \
         research/Metamerism/v2/patch_v2_phaseE.py \
         research/edge-exposure-study/patch_experiment.py \
         research/checkpoint-study/patch_experiment.py; do
  python3 "$p" "$SCRATCH/engine"
done
bash "$SCRATCH/engine/build.sh" dylib
```

The promoted engine does not implement the `SPK_RESEARCH_*` hooks, so it cannot
generate a negative or a tap. That is why the oracle exists and why it is
hashed, not why it is trusted.

## 3. The frozen model

| property | required value |
|---|---|
| input domain | three recovered log10-positive channels (before DI matrix / clamp / Cineon) |
| output | paper CMY density; the existing scan and output transform follow |
| grid / interpolation / storage | 65³ / trilinear / float32 |
| look retention | `r_blend = 1.0` |
| tone / gamut mapping | `ymode = 'opt'`, `mode = 'hybrid'` |
| production print EV | `0.0` |
| calibration spaces | separate sRGB and ProPhoto RGB builds |
| DI matrix | per pair and space, white-pinned E1-C3 refit on the chain's positives, DIR 1.0 |
| sampling | chart 67, grey ramp, 1,628-spectrum fit set, the film's own photograph; Portra keeps its C1 photographs |
| gamut mapping | hybrid, range limits at the 99.5th percentile of the pair's own overshoot |

At r = 1 the target keeps the optical chain's Oklab lightness and chroma and
takes the DI reading's hue, with the existing near-neutral fallback. The
`ev = 0.032` chart tables are diagnostic artifacts and never replace a
production table.

## 4. Workspace

```sh
WORK="$RESEARCH_VOLUME/SpektraLab_research/2026-10-24_metamerism_v2/minilab-allpairs"
```

- `WORK/v2`, `WORK/study` — an isolated copy of the research code and small
  outputs. Never the original tree.
- `WORK/inputs`, `WORK/data`, `WORK/.venv` — read-only symlinks.
- `WORK/resources` — what the oracle reads: the base resources plus the
  product's alias profile as shipped.
- `WORK/host_resources` — the same bytes with aliases materialised for the
  numpy replica, and the alias neutral-filter row the engine falls back to.
- `WORK/run` — ledger, jobs, published tables, sheets, reports.

`prepare.py` builds both overlays and the per-film `anchor_C0` (the D55 white
anchor through the film's own C0 table, `study/e2lib.py:anchor`). The four
research films reuse their recorded file; the other thirteen are generated.
No anchor is a guessed constant.

## 5. The frozen canary

Before any new pair:

```sh
$PY engine/tools/minilab_bake/bake.py --work "$WORK" --oracle "$ORACLE" --verify-canary
```

It re-bakes Portra 400 → Portra Endura in both spaces **through the generalized
wrapper** and compares bytes with the committed files. The committed hashes are
`bee5f4b4…` (sRGB) and `b62650ec…` (ProPhoto). A difference means the wrapper
is not the approved recipe; stop and fix it, do not "reproduce from a sidecar".

## 6. The queue

```sh
$PY engine/tools/minilab_bake/sweep.py --work "$WORK" --oracle "$ORACLE"
```

- one `bake.py` child at a time, `--timeout` bounded, fresh process per job;
- ordering: every film's own `target_print` pair first, then the remaining
  papers film by film, each pair sRGB then ProPhoto;
- the ledger is written atomically before and after each child; a child with no
  `status.json` becomes `bake_failed` with the tail of its log and is retried
  only with `--retry`;
- a local failure never deletes or overwrites another pair's artifacts and never
  stops the queue.

Measured throughput on this machine (M3 Max, one child): ~180–230 s per pair and
space through the full gate set, so the remaining 100 pairs / 200 tables are
roughly 11–13 hours of wall time. The queue is resumable at any point: stop it,
re-run the same command, and every `integrated_verified` / `visual_pass` entry is
skipped. To finish the sweep in batches, use `--max-jobs N` and then, after
inspecting the new sheets:

```sh
$PY engine/tools/minilab_bake/report.py mark --work "$WORK" --oracle "$ORACLE" \
    --ids <ids> --state visual_pass --note "sheet reviewed"
$PY engine/tools/minilab_bake/stage.py --work "$WORK" --oracle "$ORACLE" --qualified
$PY engine/tools/minilab_bake/verify_native.py --work "$WORK" --oracle "$ORACLE" --ids <ids>
$PY engine/tools/minilab_bake/report.py summary --work "$WORK" --oracle "$ORACLE"
```

Do not run `mark`/`stage` while a sweep is writing the same ledger: both rewrite
the whole file, and although the state machine refuses to move a pair backwards,
a whole-file write can still lose a key. Stop the sweep between batches.

## 7. Per-pair gates

Numeric (`bake.py`, recorded in `gates.json`):

| gate | requirement |
|---|---|
| artifact | 3,295,528 bytes, side 65, finite payload and ordered bounds, correct ids/space, EV 0, r 1 |
| paper solve | `n_fallback_final_unsolved == 0`, `resid_max <= 0.002` |
| domain | inversion failures, mapped nodes, physical fraction and occupied span reported; never concealed by deleting hard nodes |
| LUT vs direct | same target function solved without the table; the gate is the approved r=1 photograph-mean envelope × 1.25 (≤ 0.175, `FINDINGS.md` §1). Chart mean/max, photograph p99, the SOP 0.2/0.05 and per-space values are recorded and flagged, not gated |
| identity | optical chain expressed in the same domain: photograph mean ≤ 24, max ≤ 216 codes (frozen Portra limits, inherited provisionally and reported) |
| tone/order | photograph inverted-pair fraction ≤ 1.5× the DI arm + 0.001 (sampling allowance, `FINDINGS.md` §5); Spearman reported and flagged at 0.005 below the DI, not gated |
| colour/look | hue, chroma ratio and ΔE00 by chart group for both arms — a record, not an accuracy certificate |

Human (`report.py mark --state visual_pass`): the colour-chart sheet in
`run/sheets/<id>.jpg`, optical / DI / minilab in one display transform. A pair
without that mark stays `numeric_pass`, not `qualified`.

Batch (`verify_native.py`, `minilab_resource_checks.py`):

- RGBA16 bit-exact between the research build with
  `SPK_RESEARCH_MINILAB_LOGPOS=<staged table>` and the promoted engine reading
  the same file through the bundle resources;
- missing catalog, corrupt table, missing table, changed named profile, and for
  an alias, changed inherited base profile must each fail explicitly; an
  uncatalogued pair must keep rendering on its own optical path.

## 8. Staging

```sh
$PY engine/tools/minilab_bake/stage.py --work "$WORK" --oracle "$ORACLE" --ids "$IDS"
$PY engine/tools/minilab_bake/verify_native.py --work "$WORK" --oracle "$ORACLE" --ids "$IDS"
$PY engine/tools/minilab_bake/report.py summary --work "$WORK" --oracle "$ORACLE"
$PY engine/tools/minilab_bake/report.py verify-staged --work "$WORK" --oracle "$ORACLE"
```

`stage.py` writes `<film>__<paper>.lut3d` (sRGB) and `_pp.lut3d`, then the
catalog entry with FNV-1a 64-bit hashes of the table, the named profile and —
for a `derived_from` alias — the inherited base profile. It refuses an existing
entry unless `--replace`. `verify-staged` re-derives every hash from the files.

The runtime loader change that makes the alias entry meaningful is
`engine/src/core/minilab.cpp`: `film_base_hash` / `paper_base_hash` are checked
only when present; an entry that declares one on a non-alias profile is an
error. `engine/tests/minilab_resource_checks.py --film … --paper …` proves both
the rejection and the backward-compatible path.

## 9. Regression and resource cost

- `engine/tests/v2_integration_checks.py pair --pair 'film|paper'
  --table-dir engine/resources/minilab --before "$ORACLE"
  --before-resources "$WORK/resources" --after . --after-resources
  "$WORK/run/staging/resources"` is the same check as a standalone command.
- The built bundle is checked with
  `python3 engine/tests/minilab_catalog_check.py <EngineResources>`: it
  re-derives every table and profile identity from the shipped bytes. The
  catalog is required at engine setup, so a bundle without it cannot render at
  all; both `engine/build.sh bundle` and the Mac app's
  `app/SpektraLab/tools/build_engine_mac.sh` copy `engine/resources/`
  wholesale, which carries `minilab/` with it.
- Existing Portra images, DI, B&W, positive bypass, table replacement and the
  full resource-failure matrix are run before a push.
- Runtime loading stays lazy: one table per open, bounded by the pipeline's
  existing persistent upload; the bundle is not read eagerly.
- Report the raw payload (896,383,616 bytes for 272 tables before packaging),
  cold open / first render and peak footprint against the same model with
  optimisations controlled, interleaved. Do not attribute colour changes to
  performance.

## 10. Honest limits

- The visual gate is a colour-chart sheet inspected by a person or an image-
  capable agent; it is not a substitute for independent photography. The tone
  and identity gates do use a real photograph, but only the one this study
  carries for every film.
- The numeric limits for a new film inherit Portra's provisional identity and
  look references; a miss is reported, never relaxed.
- A pair that fails stays on the optical path and stays visible in
  `COVERAGE.md` with its state and reason.
