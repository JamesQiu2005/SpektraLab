# All-pair minilab baker (offline)

This directory is the parameterized version of the research baker that produced
`engine/resources/minilab/kodak_portra_400__kodak_portra_endura*.lut3d`. It
exists so that "bake this pair too" is a command with an explicit film, paper
and calibration space rather than a renamed copy of a Portra script.

**Offline only.** Nothing here is imported by the app, the engine build, or
`engine/build.sh bundle`. The product builds from the tracked tables; a new
calibration needs Python, the research tree and a patched disposable engine,
exactly like `engine/tools/bake_resources.py`. See
`engine/minilab-coverage/SOP.md` for the model rules this implements.

## The frozen model

Every table uses this recipe explicitly, never a function default:

| property | value |
|---|---|
| input domain | three recovered log10-positive channels, before the DI matrix/clamp/Cineon |
| output | paper CMY density (the existing scan and output transform follow) |
| grid / interpolation / storage | 65³ / trilinear / float32 |
| look retention | `r_blend = 1.0` |
| tone / gamut mapping | `ymode = opt`, `mode = hybrid`, `ev = 0.0` |
| calibration spaces | separate sRGB and ProPhoto RGB builds |
| DI matrix | per-pair, per-space white-pinned E1-C3 refit (`e1x.Data(...).fit3()`) |
| DIR amount | 1.0 (the shipped default the matrix is fitted at) |

The scientific call sequence is `v2/c3_lib.py::build` kept literal in
`bake.py::build_table`. `--verify-canary` re-bakes the two committed Portra
tables and compares bytes; that is how any change here is proven not to have
moved the model.

## Prerequisites

1. **An isolated research copy.** `research/Metamerism` copied somewhere with
   `inputs/` and `data/` symlinked read-only, plus the research `.venv`. Nothing
   writes through a symlink into the original tree.
2. **A disposable oracle engine.** The promoted engine does not carry the
   `SPK_RESEARCH_*` hooks, so the negatives and taps must come from a build of
   the recorded source revision plus the recorded patch order
   (`engine/performance/2026-10-24/provenance.json`). The patches refuse any
   path outside `/private/tmp`:

   ```sh
   SCRATCH=/private/tmp/minilab-bake-oracle
   git archive unpublished-revision engine | tar -x -C "$SCRATCH"
   for p in research/Metamerism/study/patch_experiment.py \
            research/Metamerism/v2/patch_v2_print.py \
            research/Metamerism/v2/patch_v2_minilab.py \
            research/Metamerism/v2/patch_v2_phaseE.py \
            research/edge-exposure-study/patch_experiment.py \
            research/checkpoint-study/patch_experiment.py; do
     python3 "$p" "$SCRATCH/engine"
   done
   bash "$SCRATCH/engine/build.sh" dylib
   ```

   The six patch scripts are hashed into the ledger; a drifted patch is a
   different harness, not an optimisation.
3. **The production engine built** (`engine/build.sh dylib`) for the runtime
   gate, because the gate compares the promoted engine with the oracle.

## Commands

```sh
BAKE=engine/tools/minilab_bake
PY=<research copy>/.venv/bin/python

# 1. overlays (base + product alias materialised for the replica) and per-film
#    exposure anchors, generated by the existing spectral procedure
$PY $BAKE/prepare.py --work <copy> --oracle <oracle>

# 2. prove the harness still reproduces the approved Portra tables, byte for byte
$PY $BAKE/bake.py --work <copy> --oracle <oracle> --verify-canary

# 3. the queue: one child process per job, atomic ledger, resumable
$PY $BAKE/sweep.py --work <copy> --oracle <oracle> --max-jobs 2
$PY $BAKE/sweep.py --work <copy> --oracle <oracle> --films kodak_gold_200 --spaces sRGB

# 4. inspect run/sheets/<id>.jpg, then mark the pair reviewed
$PY $BAKE/report.py mark --work <copy> --oracle <oracle> \
    --ids kodak_gold_200__kodak_2383__srgb,... --state visual_pass --note "..."

# 5. copy qualified tables into engine/resources/minilab and update index.json
$PY $BAKE/stage.py --work <copy> --oracle <oracle> --ids <same ids>

# 6. runtime execution gate: same table, research build vs promoted engine
$PY $BAKE/verify_native.py --work <copy> --oracle <oracle> --ids <same ids>
python3 engine/tests/minilab_resource_checks.py --film ... --paper ... --output /tmp/r.json

# 7. coverage report (writes engine/minilab-coverage/COVERAGE.md)
$PY $BAKE/report.py summary --work <copy> --oracle <oracle>
$PY $BAKE/report.py verify-staged --work <copy> --oracle <oracle>
```

## What a job directory holds

`<out>/jobs/<film>__<paper>__<srgb|pp>/`

| file | kept in git? | meaning |
|---|---|---|
| `table.lut3d` | only when staged | 3,295,528 bytes, the production artifact |
| `sidecar.json` | no | domain, solve statistics, range-limit tables |
| `nodes.npz` | no | per-node masks and residuals (evidence) |
| `fit.json` | no | E1-C3 matrix, conditioning, held-out statistics |
| `gates.json` | no | every gate with numbers and pass/fail |
| `manifest.json` | no | profile/source/dataset/engine/package identity |
| `identity.lut3d` | no | the optical chain in the same domain (control) |
| `sheet.jpg` | no | colour-chart sheet: optical / DI / minilab |
| `status.json` | no | last completed stage |

The ledger is `<out>/ledger.json`; it is written through a temp file and
`os.replace` after every transition. `status.json` is written inside a
`.tmp-*` directory and the whole directory is renamed into place, so a killed
job never leaves a half-written table where the sweep would trust it.

States: `pending → preflight_ok → fitting → fitted → baking → baked →
numeric_pass → visual_pass → qualified → staged → integrated_verified`.
Failures stay visible: `blocked_input`, `fit_failed`, `bake_failed`,
`gate_failed`, `needs_visual_review`.

## Gates

Numeric, per pair and space (`bake.py`):

- **artifact contract** — exact length, side 65, finite payload, finite ordered
  bounds, EV 0, r 1, matching ids and space.
- **paper solve** — `n_fallback_final_unsolved == 0`, `resid_max <= 0.002`.
- **domain** — inversion failures, mapped nodes, physical fraction, occupied
  span. Reported, never "fixed" by deleting hard samples.
- **LUT vs direct** — the same target function solved without the table at the
  67 chart negatives and a 4,000-pixel photograph sample. The gate is the
  approved r=1 artifact's photograph-mean envelope × 1.25 (≤ 0.175); the chart
  mean and max, the photograph p99 and the SOP's 0.2/0.05 are still evaluated,
  flagged and recorded. `engine/minilab-coverage/FINDINGS.md` §1 has the
  measurements behind that decision.
- **identity control** — the optical chain expressed as a table in the same
  domain, rendered through the same hook: photograph mean ≤ 24 and max ≤ 216
  codes. Frozen Portra numbers; inherited provisional limits for a new pair and
  reported, not passed by relaxation.
- **tone/order** — 20,000 pixel pairs on a real photograph: inverted fraction
  ≤ 1.5× the DI arm + 0.001 (an 18.7-pair sampling allowance; the DI arm itself
  moves 4× across films). Spearman is reported and flagged 0.005 below the DI,
  not gated. `FINDINGS.md` §5.
- **colour/look** — hue, chroma ratio and ΔE00 by chart group for both arms. A
  record, not an accuracy certificate.

Human, per pair (`report.py mark`): the chart sheet. `needs_visual_review` is a
real state, not a timeout — a pair that was never looked at is not qualified.

Batch, per pair and space (`verify_native.py`,
`minilab_resource_checks.py`): RGBA16 bit-exactness between the research build
and the promoted engine reading the *same* table, and the resource-failure cases
(missing catalog, corrupt table, missing table, changed named profile, and for
an alias, changed inherited base profile).

## Memory and storage

One child process per job, `subprocess`-bounded by `--timeout`. A job releases
its arrays at exit. Peak RSS is recorded by the child and in the ledger; it is
RSS, not physical footprint — the Metal pool is invisible to it.

The raw payload for all 136 colour pairs is 896,383,616 bytes (~855 MiB) before
packaging, plus evidence. Evidence stays in `<out>`, never in git. Nothing
stages a pair that did not pass both numeric and visual gates.

## What this does not do

- It does not bake at runtime and the engine has no file writer.
- It does not turn a B&W or reversal pair into a colour minilab job: those
  routes keep their own runtime paths and are reported separately.
- It does not claim "more accurate". The gates bound interpolation, domain and
  port errors; the look is the film/paper character the model already had.
